# DT7 / DR16 接收机调试笔记

> 适用范围：本仓库（`F:\robomaster\chasis`，STM32H723VGTx + FreeRTOS + AC6 + csolution）
> 以及任何"大疆 DT7 遥控器 + DR16 接收机 + DBUS 单线串口"的项目。
>
> 本文全部结论都来自本机实测（2026 年那次把接收机从"完全收不到"调到"整车正常"的
> 全过程），不是抄手册。凡是"实测"标记的，都是踩过坑换来的，建议直接照用。

---

## 0. 一句话结论

那次连续几天收不到遥控数据，**根因不是协议、不是波特率、不是极性，而是"用 DMA 双缓冲
方式收一个 1285 B/s 的低速串口"**。这套方案对 `DBM/CIRC/NDTR/CT/DMAMUX/IDLE` 的时序依赖
太多，任何一处不对整条链路就静默失效，且没有任何可观测点。改成**字节中断 + IDLE 切帧**
之后立刻正常。

配套的第二大坑是**遥控丢失没有保护**：丢帧时 buffer 保持最后一帧的值，车会按最后的摇杆
指令一直冲。这条在没接电机时不显形，接了电机就是事故。

## 1. DT7 / DR16 协议速查（背下来）

| 项 | 值 | 备注 |
|---|---|---|
| 接口类型 | **DBUS** | **不是 SBUS**。25 字节帧就是 SBUS，直接判死 |
| 波特率 | `100000` | |
| 帧格式 | 8 数据位 + **偶校验** + 1 停止位（8E1） | STM32 HAL 里就是 `WORDLENGTH_8B` + `PARITY_EVEN` + `STOPBITS_1` |
| 帧长 | **18 字节** | |
| 帧周期 | **14 ms** ≈ 71 帧/秒 | 用帧率判断链路是否活着最快 |
| 数据速率 | 18 × 71 ≈ **1285 B/s** | 这个量级**绝不该用 DMA** |
| 信号极性 | DBUS 原生**反相**（空闲低） | 板上有硬件反相器 → 软件不反相；没有 → 开 RXINV |
| 通道范围 | `364 ~ 1684`，**中位 1024** | `(raw - 1024) / 660.0f` → -1.0 ~ +1.0 |
| 拨码值 | `1 = UP`，`2 = DOWN`，`3 = MID` | 安全开关写 `== sw_up`(1)，不要写 `!= sw_down` |
| 供电 | 5 V | **必须与 MCU 共地** |

### 18 字节帧布局（位区间 + 代码表达式）

`p[]` 为帧缓冲区；通道均为 11 位，鼠标/键盘为小端 16 位。

| 字段 | 位区间 | 提取方式 |
|---|---|---|
| ch0 右水平 | 0–10 | `(p[0] \| p[1] << 8) & 0x07FF` |
| ch1 右竖直 | 11–21 | `((p[1] >> 3) \| (p[2] << 5)) & 0x07FF` |
| ch2 左水平 | 22–32 | `((p[2] >> 6) \| (p[3] << 2) \| (p[4] << 10)) & 0x07FF` |
| ch3 左竖直 | 33–43 | `((p[4] >> 1) \| (p[5] << 7)) & 0x07FF` |
| sw0 左拨码 | 44–45 | `((p[5] >> 4) & 0x0C) >> 2` |
| sw1 右拨码 | 46–47 | `(p[5] >> 4) & 0x03` |
| 鼠标 X | 48–63 | `p[6] \| (p[7] << 8)` |
| 鼠标 Y | 64–79 | `p[8] \| (p[9] << 8)` |
| 鼠标 Z | 80–95 | `p[10] \| (p[11] << 8)` |
| 鼠标左/右键 | 96–97 | `p[12]` / `p[13]` |
| 键盘 | 98–113 | `p[14] \| (p[15] << 8)` |
| 拨轮 | 114–124 | `(p[16] \| (p[17] << 8)) & 0x07FF` |

> 注意：上表"位区间"是按 18 字节总位宽（144 位）算的偏移，鼠标/键盘那个区间只是示意，
> 实际以代码里按字节取的方式为准（`p[6..15]`）。

## 3. 上电自检流程（每次接新接收机照这个走）

### 第 0 步：确认固件真的在跑

看串口有没有这一行（`BSP_Init_DebugUart()` 之后立刻直发，绕过队列和任务）：

```
[boot] USART10 direct write OK
```

- **没有** → 固件没跑起来（烧写失败 / 供电 / 接线），**不要再去查协议**
- 有 → 继续

### 第 1 步：看累计字节数 `by`

```
[rc] frm=0 bad=2 bi=2 len=0/0 ne=0 ore=0 inv=0 by=0 pin=1/1/6300
```

| 现象 | 结论 |
|---|---|
| `by` 不涨 | 线上没有数据 → 接收机没供电 / 没接线 / **遥控器没开机** |
| `by` 在涨 | 有字节进来，继续第 2 步 |

`pin=` 是直接读 PD2 电平的探针（绕开 UART）：

- `pin=1/1/xxx`（边沿数恒为 1）→ 线被稳定拉高，**接收机有电但没在发数据** → 无线链路断了（遥控器关机/失配）
- `pin=1/几千/xxx`（边沿数一直涨）→ 线上有数据在跑 ✓

### 第 2 步：看帧长 `len`

| `len` | 结论 |
|---|---|
| **18/18** | ✅ 正确，DBUS |
| **25** | 是 **SBUS**，不是 DBUS。要改解析器（帧长 25、通道布局不同） |
| **19 / 20** | 字长或校验位配错（多算/少算一位） |
| **0** | `by` 在涨但切不出帧 → IDLE 检测或缓冲长度有问题 |

### 第 3 步：看坏帧数 `bad`

`bad` 应该在上电后稳定在一个小数字（本工程实测是 **2**，启动那两帧），之后不再增长。

- `bad` 按 ~70/秒 增长 → 帧在来但每帧长度都不对 → 回第 2 步

### 第 4 步：看通道原始值 `raw`

```
[rc] sw=1,1 raw=1024,1024,1024,1024,1024 pct=0,0,0,0,0 en=1
```

- 摇杆回中 → 5 个 `raw` 都应在 `1024 ± 20`
- 拨左摇杆 → 只有 `raw[2]`（左水平）、`raw[3]`（左竖直）变化
- 拨右摇杆 → 只有 `raw[0]`、`raw[1]` 变化
- 拨拨码 → `sw` 在 1/2/3 之间跳

### 第 5 步：确认安全开关

`en=1` 需要**同时**满足两个条件（本工程已实现）：

1. 左拨码 = `sw_up`（1）
2. 遥控帧没有超时（100 ms 内收到过新帧）

## 4. 可信指标 vs 不可信指标（这条最省时间）

| 指标 | 可信？ | 说明 |
|---|---|---|
| **`len`（帧长）** | ✅ **最可信** | IDLE 时实测的字节数，直接反映帧边界 |
| **`bad`（坏帧数）** | ✅ 可信 | 帧长≠18 的次数 |
| **`by`（累计字节数）** | ✅ 可信 | 一直不涨 = 线上没数据，一秒定位 |
| `pin`（引脚电平探针） | ✅ 可信 | 绕开 UART 直接读 GPIO，用来区分"没信号"和"解不出" |
| **`fe`（帧错误）** | ❌ **不可信** | H7 上 FE 标志置位/清除时序有问题，实测 ~78% 字节"报错"而数据完全正确；**改校验位配置它纹丝不动**。第一次排查被它带偏两轮，改 parity 又改回来，纯浪费 |
| **`ndtr`（DMA 剩余）** | ❌ 不可信 | 2 ms 采样 × 14 ms 帧率，14/2 = 7 整数倍，永远采在同一相位，恒 20 是假象 |
| `ore`/`ne` | 参考 | 各一两次且不增长 = 上电瞬间的，可忽略 |

> **教训：动手改配置之前，先确认"这个指标真的会随配置变化"。** 一个可信指标胜过五个可疑指标。

## 5. 两个必须有的保护

### 5.1 遥控超时 → 停车（安全底线）

**为什么必须有**：`RcDataUpdate()` 只在收到帧时更新数据。遥控器关机/失联/线松之后，
缓冲区会**保持最后一帧的值** —— 拨码仍然返回 UP、摇杆仍然返回最后的位置 → 车按最后
那个指令一直跑，直到撞墙。

```c
/* 控制环里（2 ms 一次） */
static uint32_t rcLastFrm = 0U;
static uint16_t rcLostCnt = 0U;
uint32_t rcFrm = Get_RC_FrameCount();

if (rcFrm == rcLastFrm) { if (rcLostCnt < 0xFFFFU) rcLostCnt++; }
else                    { rcLastFrm = rcFrm; rcLostCnt = 0U; }

rcOk = (rcLostCnt > 50U) ? 0U : 1U;      /* 50 × 2ms = 100ms，约丢 7 帧 */

/* 拨码 UP 且遥控在线，才允许输出 */
enable = ((Get_Switch_Value(Switch_Left) == sw_up) && (rcOk != 0U)) ? 1U : 0U;
```

**现场验证方法（一定要做一次）**：车跑起来后直接关遥控器 → 车应在 100 ms 内停下，
串口打出：

```
[evt] RC link LOST -> motors forced stop
```

重新开遥控器 → `[evt] RC link OK`。

### 5.2 拨码当安全开关

只有 `sw_up`(1) 才输出，其它位置（DOWN=2、MID=3、未初始化=0）一律停车。
**不要写 `!= sw_down`** —— 上电瞬间拨码可能还没稳定。

## 6. 接收机驱动写法（推荐照抄这个结构）

```
UART 配置：100000 / 8 数据位 / 偶校验 / 1 停止位 / 不反相
中断使能：RXNE（字节中断） + IDLE（切帧）
不需要 DMA、不需要双缓冲、不需要"翻 CT"
```

中断服务骨架：

```c
void RC_IRQHandler(UART_HandleTypeDef *huart)
{
    /* 1. 先取 ISR 快照：H7 上"读 RDR"会顺带清 PE/FE/NE，晚了就统计不到 */
    uint32_t isr = huart5.Instance->ISR;

    /* 2. 把现成的字节全部取走（H7 的标志名是 RXNE_RXFNE，不是 RXNE！） */
    while ((huart5.Instance->ISR & USART_ISR_RXNE_RXFNE) != 0U)
    {
        uint8_t b = (uint8_t)(huart5.Instance->RDR & 0xFFU);
        /* 计数 + 存缓冲，索引可以超过 18，用来观察真实帧长 */
    }

    /* 3. IDLE = 一帧结束：按"实际字节数"判断，== 18 才解析 */
    if (isr & USART_ISR_IDLE)
    {
        huart5.Instance->ICR = USART_ICR_IDLECF;
        记录 len = 本帧字节数;
        if (len == 18) 解析;
        else           计坏帧;
        索引清零;
    }
}
```

### 三个必须注意的细节

1. **`xxx_IRQHandler()` 里不要调用 `HAL_UART_IRQHandler()`**
   HAL 的错误处理会去读 `RDR` 清 FE/NE，等于**把你的字节吃掉**。自己接管就完全接管。

2. **H7 的 RXNE 标志名是 `USART_ISR_RXNE_RXFNE`**
   没有 `USART_ISR_RXNE` 这个宏，写错就是编译错误。

3. **极性配置只允许有一个权威来源**
   那次踩的坑：`usart.c` 里关掉了 RXINV/DATAINV，但业务代码里有个 `RC_Dbg_InvertMode`
   默认值 1，控制环第一拍就调 `RC_ApplyInvert()` 把 `usart.c` 的设置**覆盖回去**了 ——
   看配置永远查不出问题。
   同理 `DATAINV` 只反数据位、不反起止位，对 DBUS 只会产生乱码，**永远不要开**。

## 7. 接上电机那天的验证顺序

1. **车架空**（轮子离地）
2. `WheelSign` 先全部设 `+1`
3. 只让一个轮子转：`Target[i] = 500`，其余 0 → 确认 ①这个 CAN ID 对应这个物理位置
   ②转向符合"轮子向前滚"
4. 四个轮子逐个验证完，再定 `WheelSign`
5. 验证整体三轴：分别只推**前进**、只推**右平移**、只推**右转**，看 `T` 的符号组合
   - 前进：四轮同号
   - 横移：左右两侧反号
   - 旋转：左右两侧反号
6. 落地低速试跑

**逆解算公式可以用日志交叉验算**（本次就是这么确认公式没错的）：
取一行 `[rc]` 的 `pct` 算出 `vx/vy/wz`，代入公式得 `T`，与紧随其后的 `[mtr]` 行对比，
四轮误差应在 2% 内（差值来自两行打印之间摇杆又动了一点）。

## 8. 那次踩过的所有坑（对照表）

### 8.1 构建 / 工具链

| 现象 | 根因 | 修法 |
|---|---|---|
| 链接报 `L6218E: Arm_Motor / Queue_CANSend` | `cproject.yml` 里**没有任何 BSP 源文件**，也没加 `../BSP/Inc` 包含路径 | 补 group + 包含路径 |
| csolution 加载阶段直接报错 | 引用了不存在的 `portable/Common/mpu_wrappers_v2.c` | 注释掉（`configENABLE_MPU=0` 用不上） |
| `__forceinline` / `__asm { }` 满屏报错 | 用了 **`RVDS/ARM_CM4F`** 移植层（ARMCC5 专用内嵌汇编），工具链是 **AC6/armclang** | 换 `portable/GCC/ARM_CM4F`（`__attribute__((naked))` + GNU asm） |
| `QueueHandle_t` 未定义 | `sysconfig.h` 的包含链里没有 `queue.h` | 显式 `#include "FreeRTOS.h"` + `"queue.h"` + `"task.h"` |
| `USART_ISR_RXNE` 未定义 | H7 上叫 `USART_ISR_RXNE_RXFNE` | 改名 |

### 8.2 调试器（pyOCD + 正点原子无线 DAP）

| 现象 | 根因 | 修法 / 结论 |
|---|---|---|
| `Unable to read memory @0xe000ed14 / ed10` | 是 `SCB->CCR` / `SCB->SCR`。pyOCD 探测 Cortex-M7 PPB ROM 表第一项（SCS）失败；H7 需要先配 `DBGMCU_CR`，且**不能 connect-under-reset** | 改 `connect_mode=attach`、降 SWD 时钟、或用用户脚本写 `DBGMCU_CR` |
| csolution 里 `clock: 10000000` | 10 MHz 是**有线**调试器的默认值，无线链路必挂 | 降到 100 kHz（`MDK-ARM/Engineer_CusCtrlr.csolution.yml` 的 `target-set → debugger → clock`） |
| 擦除停在 36%，`expected DAP_SWJ_SEQUENCE` | 无线链路在长事务里 desync，属硬件层 | **烧写一律用有线**；无线只用于"能连上看一眼" |
| 板子完全静默、串口一字节都没有 | 上一次烧写在擦除中断了 → 空白/半截 Flash | 重烧必须看到进度 100%；先在 `main()` 加"直发一行"的最小验证点 |

### 8.3 接收机

| 现象 | 根因 | 修法 |
|---|---|---|
| `len=0/0`，IDLE 按帧率触发，`fe` 有值 | **DMA 双缓冲方案失效**（字节根本没进 DMA） | 改用字节中断 + IDLE 切帧 |
| 收到 0 字节但 `ore=0` | `HAL_UART_IRQHandler()` 在错误处理里读 `RDR` 把字节吃掉了 | 从 `UART5_IRQHandler()` 里删掉 `HAL_UART_IRQHandler()` |
| 配置里关着反相，运行时却是开的 | `RC_Dbg_InvertMode` 默认值 + `RC_ApplyInvert()` 每拍覆盖 | 两处配置必须一致，且只保留一个权威来源 |
| `fe` 一直涨但数据全对 | FE 标志在 H7 上的观测假象 | **忽略 fe**，看 `len`/`bad`/`by` |
| 调试行尾部数据"消失" | 调试缓冲 96 字节太小，`sizeof-3` 截断 | 缓冲加到 160 字节 |
| 摇杆数据全 1024、`en` 恒 0 | 遥控器没开机（`pin` 边沿数恒为 1 可确诊） | 开遥控器 / 检查接收机指示灯 / 重新对频 |

### 8.4 我自己的两次误判（学习点）

| 误判 | 错在哪 | 教训 |
|---|---|---|
| 用"串口能读"推出 SYSCLK = 500 MHz，进而算出 CAN 波特率 +4.2% 误差，建议改 `fdcan.c` | `HAL_UART_Init()` 是**按实际外设时钟现算 BRR** 的，串口正常**推不出**时钟树 | 别用间接现象反推底层参数；实测电机正常 → FDCAN 时钟约 80 MHz（HSE=24）→ 正好 1.000 Mbps，`fdcan.c` 不用改 |
| 把 `fe` 增长归因于帧宽/校验位不匹配，改了 parity | 改完之后 `fe` 纹丝不动 | **改配置前先做"这个改动是否真的影响该指标"的验证** |

[mtr] seq=1665 en=1 ld=0 T 2059 1795 2059 1795 S 1980 1830 2010 1770 I 3200 3150 3300 3250 drop=0

| 字段 | 含义 |
|---|---|
| `frm` | 成功解出的帧数（≈71/秒） |
| `bad` | 帧长≠18 的次数（正常只有启动那 2 次） |
| `bi` | 缓冲下标，`2` = 复位态（不正常） |
| `len` | 最近一帧 / 曾见最大帧长，DBUS 应为 `18/18` |
| `ne` / `ore` | 噪声 / 溢出计数，上电各一两次可忽略 |
| `inv` | 当前 RXINV 极性（本板应为 0） |
| `by` | 累计字节数，应严格按 `18 × 帧率` 增长 |
| `pin` | PD2 电平 / 边沿数 / 高电平采样数 |
| `sw` | 左、右拨码值（1=UP 2=DOWN 3=MID） |
| `raw` | 5 个通道原始值（1024 = 中位，364~1684） |
| `pct` | 5 个通道百分比 |
| `en` | 允许输出标志（拨码 UP 且遥控在线） |
| `ld` | 电机掉线位图，bit0..3 = 左前/左后/右后/右前；`15` = 四路全掉线 |
| `T` | 四轮目标转速（转子 rpm） |
| `S` | 四轮反馈转速 |
| `I` | 四路电流指令（±16000） |
| `drop` | 调试消息因队列满被丢弃的条数 |

## 10. 快速排障表

| 现象 | 结论 | 动作 |
|---|---|---|
| 串口连 `[boot]` 都没有 | 固件没在跑 | 查烧写（进度是否 100%）、供电、PE3→RXD、GND |
| `by=0`、`pin` 边沿恒 1 | 接收机有电但没发数据 | 开遥控器 / 看接收机指示灯 / 重新对频 |
| `by=0`、`pin` 边沿在涨 | 线上有数据但 UART 没收 | 查波特率是否 100000、RXNE 中断是否使能、`HAL_UART_IRQHandler` 是否还在抢 |
| `by` 涨、`len=25` | 是 SBUS | 改解析器（帧长 25、布局不同） |
| `by` 涨、`len=19/20` | 字长/校验位错 | 检查 `WORDLENGTH` / `PARITY` |
| `by` 涨、`len=0` | 切帧逻辑坏 | 检查 IDLE 使能、`RC_IRQHandler` 是否被调用 |
| `len=18`、`bad` 按 70/秒 涨 | 每帧都判错但长度是 18 | 检查 `RC_FRAME_LEN` 定义、解析分支 |
| `raw` 全 1024、摇杆不动 | 通道解析错 或 遥控未对频 | 对照 §1 布局表逐字节核 |
| 某一路 `raw` 不随摇杆变 | 该轴坏了或拨错 | 换接收机试 |
| `sw` 一直是 0 | 帧没解出（走的是默认值） | 先修帧长 |
| `en=0` 但拨码在 UP | 遥控超时保护生效 | 看 `frm` 是否在涨；可能是丢帧 |
| `ld=15` 而电机转不起来 | 没接电调 / CAN 没通 / ID 不对 | 查电调供电、CANH/CANL、终端电阻、ID |
| `T` 有值但 `S` 恒 0 | 电调没反馈 | 以上 |
| `S` 与 `T` 反号 | 该轮 `WheelSign` 错 | 翻对应位的符号 |
| 车按最后指令直冲、摇杆无反应 | 遥控掉了但没做超时保护 | 见 §5.1，必须实现 |

## 11. 已知遗留项（不影响当前使用）

| 项 | 说明 |
|---|---|
| `Task_Can.c` 里的 `CAN_Init(&hfdcan1)` | `main` 里已初始化过，这里再调会让 FDCAN 二次进 INIT，那一瞬可能丢一帧反馈。建议删除 |
| `RC_ApplyCfg()` / `RC_AutoScan()` / `RC_ScanLocked()` / `RC_ScanCfg()` | 帧格式自动扫描的接口，调用已注释（`cfg=0` 即正确配置）。属死代码 |
| `RC_PinBurst()` | 在 `#if 0` 里，未被引用，可能有 `unused function` 警告 |
| `Remote_controler.offline_check` | 只写不读，超时保护改成用 `Get_RC_FrameCount()` 实现了 |
| `RC_FRAME_LEN_BACK`（=2） | 原 DMA 缓冲预留的 2 字节，字节中断方案下已无用 |

## 12. 一页速查（贴在工位上）

```
接 DT7/DR16 的 8 件事
─────────────────────────────────────────────
1. 100000 波特率、8 数据位、偶校验、1 停止位
2. 18 字节一帧、14ms 一帧
3. 通道中位 1024，范围 364~1684
4. 拨码 1=UP 2=DOWN 3=MID，安全开关写 == 1
5. 信号线接 RX，必须共地，5V 供电
6. 极性：板上有硬件反相器就不开 RXINV，反之开
7. 用字节中断收，不要用 DMA
8. 判据只看 帧长18 / 坏帧数 / 累计字节数，别看 FE
─────────────────────────────────────────────
两个必须有的保护
  · 遥控超时 100ms → 停车
  · 拨码 UP 才输出
─────────────────────────────────────────────
```
